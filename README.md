# Podkop

Маршрутизация трафика для OpenWrt.

Направляйте нужные ресурсы в туннель, а остальное — напрямую. Открытое программное обеспечение на базе [sing-box](https://github.com/SagerNet/sing-box).

> [!WARNING]
> Проект находится в стадии бета-версии. Возможны ошибки, нестабильная работа и существенные изменения функциональности.

# Отличия этого форка

Этот форк расширяет podkop под сценарий централизованного управления с VPS:

- **Курируемый профиль маршрутов «из коробки»**: зоны `.ru`, `.su`, `.рф` и P2P/BitTorrent-трафик всегда идут напрямую, а ограниченные ресурсы (блокировки РКН и геоблок зарубежных сервисов, список `russia_inside`) — через сервер. Управляется тумблерами **P2P (BitTorrent) напрямую** и **Прямые зоны РФ (.ru/.su/.рф)** в настройках.
- **Приём настроек от VPS-панели**: podkop может получать ключ прокси и профиль маршрутов с центральной панели (podkop-server). На роутере вводятся только URL панели и ключ; профиль кэшируется и применяется автоматически (в т.ч. офлайн — из кэша). См. настройки **Управление с VPS-панели**.
- **Extended-сборка sing-box**: вместо стоковой используется [EikeiDev/OpenWRT-sing-box-extended](https://github.com/EikeiDev/OpenWRT-sing-box-extended) — устанавливается автоматически скриптом установки.
- **AmneziaWG 2.0**: конфиг из приложения Amnezia VPN вставляется прямо в podkop — он сам поднимет туннель на ядерном модуле и будет маршрутизировать через него (см. ниже).
- **Серверная часть**: панель управления на VPS (компаньон к [3x-UI](https://github.com/MHSanaei/3x-ui)) для выдачи ключей и рассылки профилей маршрутов, с камуфляж-заглушкой. Код и инструкции по развёртыванию — в каталоге [`server/`](server/).

# Вещи, которые необходимо знать перед установкой

### Обновления и конфигурация
- При обновлении **обязательно** [очищайте кэш LuCI](https://podkop.net/docs/clear-browser-cache/).
- После обновления проверяйте конфигурацию — она может изменяться между версиями.
- При старте Podkop модифицируется конфигурация Dnsmasq.
- Podkop изменяет конфигурацию sing-box. Если вы используете собственную конфигурацию, заранее сохраните её.

### Системные требования
- Требуется OpenWrt 24.10 или выше.
- Необходимо минимум 25 МБ свободного места на устройстве. Устройства с флеш-памятью 16 МБ не поддерживаются.

### Важные ограничения и особенности
- Если установлен Getdomains, его [необходимо удалить](https://github.com/itdoginfo/domain-routing-openwrt?tab=readme-ov-file#скрипт-для-удаления)
- Dashboard доступен только при подключении по HTTP (из-за особенностей Clash API). При использовании HTTPS или домена работа может быть недоступна.

### Поддержка и диагностика
- [Руководство по диагностике](https://podkop.net/docs/diagnostics/)
- Актуальные изменения публикуются в [Telegram-чате](https://t.me/itdogchat/81758/420321). Пожалуйста, ознакомьтесь с закрепленными сообщениями.
- При возникновении проблем оставляйте технически грамотный фидбэк в GitHub Issues и Telegram-чате.

# Установка Podkop
Полное руководство доступно в [документации](https://podkop.net/docs/install/)

Для установки и обновления достаточно выполнить один скрипт:
```
sh <(wget -O - https://raw.githubusercontent.com/itdoginfo/podkop/refs/heads/main/install.sh)
```

# AmneziaWG 2.0

podkop умеет сам поднимать туннель AmneziaWG из клиентского `.conf` — того самого,
который выдаёт приложение **Amnezia VPN**. Используется ядерный модуль
(`kmod-amneziawg`), поэтому скорость выше, чем у userspace-реализаций.

**Как настроить:**

1. Установите пакеты AmneziaWG — предложит скрипт установки, либо позже:
   кнопка **«Установить пакеты»** в LuCI или `podkop awg_install`.
   Пакеты берутся из [Slava-Shchipunov/awg-openwrt](https://github.com/Slava-Shchipunov/awg-openwrt).
2. В LuCI podkop у секции выберите **Тип подключения → VPN**, затем
   **Тип VPN → AmneziaWG (импорт .conf)**.
3. Вставьте `.conf` из приложения Amnezia VPN в поле **Конфиг AmneziaWG** и сохраните.
4. Нажмите **«Применить конфиг сейчас»** (или перезапустите podkop).

podkop разложит `.conf` в `/etc/config/network` как интерфейс с `proto 'amneziawg'`
(по умолчанию `awg0`) и поднимет его. Диагностика — `podkop awg_status`.

**Что важно знать:**

- Поддерживаются параметры **AmneziaWG 2.0**: `Jc/Jmin/Jmax`, `S1–S4`, `H1–H4`
  (в т.ч. диапазоны вида `123-456`), `I1–I5`. Конфиги 1.x тоже работают.
- Параметры `J1–J3` и `Itime` **удалены в AmneziaWG 2.0** и не поддерживаются
  ядерным модулем — podkop их игнорирует с предупреждением в логе (иначе интерфейс
  не поднялся бы вовсе). Если они есть в вашем старом конфиге, это нормально.
- Полноценный AmneziaWG 2.0 доступен на OpenWrt **23.05.6+ / 24.10.3+ и новее**;
  на более старых сборках доступен только AWG 1.x — podkop предупредит об этом.
- У пира принудительно ставится `route_allowed_ips='0'`: маршрутизацией управляет
  сам podkop по спискам, иначе `AllowedIPs = 0.0.0.0/0` увёл бы в туннель весь трафик.
- Отдельная firewall-зона для интерфейса обычно не нужна: соединения инициирует сам
  роутер, а ответный трафик проходит по conntrack.

> [!NOTE]
> В этом форке скрипт установки ставит extended-сборку sing-box
> ([EikeiDev/OpenWRT-sing-box-extended](https://github.com/EikeiDev/OpenWRT-sing-box-extended)),
> а не пакет из стокового фида. Установщик extended-сборки интерактивный — он попросит
> выбрать версию sing-box. Пакет `podkop` намеренно не зависит от фидового `sing-box`,
> поэтому при ручной установке `.ipk`/`.apk` сначала установите extended sing-box.
